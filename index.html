PROJECT OVERVIEW

From container to running application.

The project uses Docker Desktop as the Minikube driver, an Nginx container image, and Kubernetes resources to run and expose the application locally.

⌘

Project objective

Deploy the official Nginx container image to a local Kubernetes cluster, expose it with a NodePort Service, verify the running Pods, and scale the Deployment to three replicas.

COMMAND REFERENCE

Steps performed, commands used.

Run these commands in Windows PowerShell. Start Docker Desktop before creating the Minikube cluster.

01
Install the toolsInstall Minikube and kubectl using WinGet.
winget install Kubernetes.minikube
winget install Kubernetes.kubectl
minikube version
02
Start the local clusterUse Docker Desktop as the Minikube driver.
minikube start --driver=docker
kubectl get nodes
03
Create and expose the applicationCreate the Nginx Deployment and a NodePort Service.
kubectl create deployment nginx-demo --image=nginx
kubectl expose deployment nginx-demo --type=NodePort --port=80
04
Verify and open the appCheck the resources and open the service URL.
kubectl get pods
kubectl get services
minikube service nginx-demo --url
05
Scale to three replicasIncrease the Deployment replica count and verify availability.
kubectl scale deployment nginx-demo --replicas=3
kubectl get pods
kubectl get deployments
!

PATH troubleshooting: If PowerShell reports that minikube is not recognized immediately after installation, open a new terminal so it reloads the updated PATH. If needed, add the Minikube installation folder to your Windows PATH.

KEY CONCEPTS

Understand the building blocks.

Kubernetes

An open-source platform for deploying, scaling, and managing containerized applications.

Minikube

A tool that runs a local Kubernetes cluster for learning and development.

kubectl

The command-line tool used to communicate with and manage a Kubernetes cluster.

Pod

The smallest deployable Kubernetes unit, containing one or more containers.

Deployment

Declares the desired number of Pod replicas and keeps that state maintained.

Service

Provides a stable network endpoint for a selected group of Pods.

NodePort

Exposes a Service on a port of each node in the cluster.

Replica

One running copy of a Pod managed by a Deployment.
